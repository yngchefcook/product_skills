# Visual design system

## Содержание

1. Темы
2. Типографика

7. Доступность

## 1. Темы

Токены хранятся в `themes.json`.

- `midnight`: технологические, финансовые и стратегические материалы; тёмные
  якорные слайды, холодный синий акцент, мягкий циан.
- `paper`: отчёты, исследования и обучение; тёплый белый фон, графитовый текст,
  синий акцент.
- `warm`: продуктовые и человеческие истории; чернильный фон, коралловый и
  янтарный акценты.
- `forest`: устойчивое развитие, инфраструктура и долгосрочные программы;
  глубокий зелёный, минеральный светлый фон, лаймовый акцент.

Не смешивать темы внутри одной деки. Допустимо менять светлый и тёмный режим
одной темы для разделителей.

## 2. Типографика

Использовать Arial для переносимости между Code Interpreter, PowerPoint и
LibreOffice.

- название деки: 50–58 pt;
- заголовок слайда: 34–40 pt;
- крупный statement/метрика: 42–64 pt;
- подзаголовок: 22–26 pt;
- основной текст: 17–20 pt;
- вторичный поясняющий текст: минимум 16 pt;
- подписи осей, метаданные и источники: 9–12 pt, только если они не несут
  основной тезис.

Использовать максимум два начертания: Regular и Bold. Иерархию строить размером,
цветом и пространством, а не множеством декоративных стилей.

## 3. Сетка и ритм

- формат 16:9;
- внешние поля 0,72–0,82 дюйма;
- единая левая линия заголовков и контента;
- безопасная нижняя зона 0,35 дюйма;
- расстояние от заголовка до содержания 0,30–0,50 дюйма;
- минимум 0,18 дюйма между независимыми текстовыми блоками;
- не заполнять пустоту случайным декором.

Чередовать силуэты:

1. полноэкранный визуальный якорь;
2. плоский аналитический слайд;
3. данные или сравнение;
4. statement или крупный вывод.

Не ставить подряд более трёх одинаковых композиций.

## 4. Композиции

- `title`: минимум текста, один визуальный фокус.
- `section`: переход главы с одной мыслью.
- `statement`: крупный тезис и короткое основание.
- `bullets`: один столбец, не более пяти пунктов.
- `image`: текст и одно изображение в пропорции примерно 42/58.
- `metrics`: 2–4 числа на общей плоскости, разделённые линиями, а не карточками.
- `chart`: диаграмма занимает основную площадь; один краткий insight рядом.
- `comparison`: две смысловые зоны с одинаковой иерархией.
- `timeline`/`process`: не более пяти этапов.
- `quote`: одна цитата, один автор, спокойный фон.
- `table`: минимум линий, выделять строку или столбец только по смыслу.
- `summary`: один синтез и 2–4 действия.
- `closing`: финальный тезис или CTA на сильном визуальном фоне.

## 5. Изображения

- использовать изображения с достаточным разрешением для 16:9;
- заранее учитывать сторону текста и оставлять negative space;
- не повторять одно изображение, кроме осознанного фонового мотива;
- не растягивать изображение с нарушением пропорций;
- не использовать изображения с водяными знаками, логотипами и читаемым
  синтетическим текстом;
- не имитировать реальные интерфейсы, графики или данные генеративной картинкой;
- при затемнении сохранять читаемый главный объект.

## 6. Диаграммы

- выбирать тип по вопросу: column — сравнение периодов, line — динамика,
  bar — ранжирование, pie — только простая доля целого;
- не использовать 3D, тени, рамки и лишние линии сетки;
- выделять акцентом одну ключевую серию, остальные приглушать;
- подписывать единицы измерения и период;
- сокращать категории до читаемого количества;
- показывать интерпретацию рядом, а не отдельным абзацем под графиком;
- круговая диаграмма — максимум шесть сегментов; мелкие доли объединять.

## 7. Доступность

- контраст обычного текста не ниже 4.5:1;
- не кодировать смысл только цветом;
- использовать прямые подписи там, где легенда заставляет бегать глазами;
- проверять видимость в grayscale;
- сохранять минимум 16 pt для любого текста, который аудитория должна прочитать
  для понимания тезиса; 9–12 pt оставлять только для служебных подписей,
  метаданных и источников.
