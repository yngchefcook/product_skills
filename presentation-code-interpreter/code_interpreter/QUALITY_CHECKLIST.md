# Delivery quality bar

Презентация готова только после выполнения всех пунктов.

## Содержание

- Коммуникационная задача сформулирована одной фразой.
- Сюжетная арка читается без устного объяснения.
- Каждый слайд имеет одну работу и один вывод.
- Все цифры и цитаты подтверждены.
- Нет внутренних заметок, TBD и placeholder-текста.
- Финал разрешает вопрос, поставленный в начале.

## Вёрстка

- Все слайды отрендерены.
- Каждый слайд просмотрен отдельно в полном размере.
- Нет обрезанного текста, неожиданных переносов и выхода за границы.
- Нет непреднамеренных наложений.
- Заголовки, поля, футеры и номера согласованы.
- Размеры шрифтов не ниже установленных минимумов.
- Изображения не растянуты и не выглядят размытыми.
- Соседние слайды не повторяют один силуэт без причины.

## Данные

- Тип диаграммы соответствует вопросу.
- Подписи, единицы, периоды и источник присутствуют.
- Цветовой акцент совпадает с выводом.
- Значения в диаграмме совпадают с исходными данными.
- Таблицы читаемы и не перегружены.

## Техническая проверка

- `lint_spec(spec)` не возвращает ошибок.
- `validate_deck.py --strict` завершается с кодом 0.
- Файл открывается после сохранения.
- Количество слайдов совпадает с планом.
- Финальный файл имеет расширение `.pptx` и ненулевой размер.

## Доставка

- Финальный `.pptx` находится в пользовательском каталоге `/mnt/data`, если он
  доступен.
- В финальном ответе есть скачиваемое вложение или кликабельная `sandbox:`-ссылка
  на фактически созданный `.pptx`.
- Имя и путь во вложении точно совпадают с результатом `build_from_spec`.
- Обычный текстовый путь без скачиваемого вложения не считается доставкой.
